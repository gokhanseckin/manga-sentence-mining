# v0.3.0 Plan — Rename, Localize, Sync, Furigana

**Status**: Planned. Not started.
**Owner**: Gokhan Seckin
**Target**: single PR landing on `main`, tagged `v0.3.0`.
**Plan effort**: max. **Develop effort**: medium (Opus 4.7).

---

## 1. Goals

1. Rename the app from "Manga Mining" to "Japanese Sentence Mining" with forward-compatible bundle id.
2. Generalize scope from manga-only to any printed/published Japanese content (manga, novels, newspapers, textbooks, children's books) via dual-prompt OCR with single-pass auto-detection.
3. Localize the interface: ship 7 bundled languages, LLM-translate any other language on demand at onboarding (blocking) or in Settings.
4. Tie the Japanese-sentence translation target to the interface language. Prompt instructions stay English; the prompt asks Gemini to *output* in the user's language.
5. Add iCloud sync (private CloudKit) for WordCards + SRS state + settings. Pages and images stay device-local.
6. Add a "Show furigana" button anywhere a Japanese sentence is rendered, sourced from existing Mecab-Swift token readings.
7. Refresh onboarding to enforce language selection on first run, with inline privacy disclosure on the API-key step.
8. Replace any manga-themed visual cues in the app icon with a neutral placeholder.

### 3.2 SwiftData schema (v3)

New fields on `WordCard`:
- `language: String` — ISO 639-1 of the translation target at card creation. Existing cards default to user's current setting on first launch (since fresh store, this is moot).
- `modifiedAt: Date` and per-field `*ModifiedAt: Date` timestamps for last-write-wins sync (or a `@Attribute` strategy detailed in §3.6).
- `sourceSnapshots: [SourceSnapshot]` — denormalized list of `(sentenceText, reading, translation, pageId, capturedAt)`. Capped to e.g. 5 most recent to bound size.

`SourceSnapshot` is a Codable struct stored as a SwiftData `@Attribute` blob, *not* a relationship (so it survives without the Sentence/Page entity).

`Page` and `Sentence` get a `documentType: DocumentType` enum (`.manga | .print`) populated from Gemini output.

`AppSettings` (or equivalent) gets:
- `interfaceLanguage: String` (drives UI + translation target).
- `furiganaPreference: FuriganaPreference` (off by default; per-screen button toggles session-only).
- `privacyAcknowledgedAt: Date?`.

Because of the bundle id change (D13), the SwiftData store on the new bundle is empty — no migration code needed. The old store stays orphaned in the old container.

### 3.3 OCR pipeline — dual-prompt, single-pass auto-detect

Single shared prompt template. Gemini returns:

```json
{
  "documentType": "manga" | "print",
  "outputLanguage": "tr",
  "panels": [...],          // populated only when documentType=manga
  "paragraphs": [...],      // populated only when documentType=print
  "sentences": [
    { "text": "...", "reading": "...", "translation": "...", "bbox": {...}, "panelIndex": 2 }
  ]
}
```

Implementation:
- `OCRPromptBuilder` produces one prompt with conditional sections: manga-extraction rules and print-extraction rules in the same prompt, gated by Gemini's own classification. The prompt explicitly tells Gemini "if manga, follow the MANGA rules; if print, follow the PRINT rules."
- `Page.documentType` stored from Gemini response.
- UI rendering branches on `documentType`: manga shows panels + reading-order overlay (existing); print shows paragraphs + linear text. v0.3.0 print rendering can start as a simple vertical list of sentences without paragraph grouping; refine later.
- No user-facing override for v0.3.0 (could add later if classification is unreliable).

### 3.4 Localization

- File format: `.xcstrings` (Xcode 15+ string catalog). Native to Apple, supports per-key comments.
- Source language: English. Each key has a `comment` field with a one-line explanation of the button's purpose for the LLM translator (e.g. `"Tap to reveal kana readings above kanji"`).
- Bundled translations: `en`, `fr`, `es`, `it`, `tr`, `ko`, `zh-Hans`. Pre-translated at build time using a build-script step (see §3.4.1) using Gemini, then committed.
- On-demand translations stored in `Application Support/InterfaceTranslations/{lang}.json` as a flat key→string map plus a `_sourceHashes: { key: sha256(en_value) }` block.
- Loading order at runtime:
  1. If `interfaceLanguage` is bundled, use the bundled `.xcstrings` directly.
  2. Else load `{lang}.json` from Application Support.
  3. Per-key fallback: missing keys fall through to English.
- Translation invalidation (D8):
  - On app launch, compute current English source hashes.
  - For each cached language file, compare per-key hashes; for any mismatch or missing key, enqueue a translation job.
  - Translation runs in background after app launch for cached languages. Onboarding-language translation is blocking.
- LLM translator: reuses `GeminiFlashProvider` (already in app). Single batch call: send all keys + comments + target language code, expect strict JSON map back. Retries via existing exponential backoff (PR #19).
- Failure mode: if Gemini returns malformed JSON or HTTP fails after retries, the language file is not written; user sees English. A non-blocking banner offers retry.

#### 3.4.1 Build-time translation script

- `Scripts/translate-interface.sh`: reads `Localizable.xcstrings`, calls Gemini for each non-bundled-but-targeted language, writes back to the catalog. Run manually before release (not in CI — needs Gemini key). Output is committed.

### 3.5 Onboarding overhaul

Three-step flow on first launch (only shown if `privacyAcknowledgedAt` is nil):

1. **Language pick**.
   - Picker pre-selects from `Locale.current` (D6).
   - Bundled languages show their endonym + flag-free typographic mark.
   - "Other language…" reveals a search field for ISO 639-1 codes.
   - On Continue:
     - Bundled → write to settings, advance.
     - Unbundled → block screen with "Translating interface to {endonym}…" + progress; success advances; failure shows English fallback prompt with Retry / Continue in English.

2. **Welcome / what is this** (single screen, no input). Localized.

3. **API key entry**.
   - Inline note (D15): "Pages you scan are sent to Google Gemini for OCR and translation. Images are not retained by Google per their API terms. Tap below to enter your API key."
   - On Save: write key to Keychain (existing), set `privacyAcknowledgedAt = Date()`, dismiss onboarding.

Settings gets a "Language" row that opens the same picker. Picking a bundled language is instant; picking an unbundled language triggers a blocking translation similar to onboarding.

### 3.6 iCloud sync

- Add `cloudKitDatabase: .private("iCloud.com.gokhanseckin.universalsentencemining")` to the SwiftData `ModelConfiguration` for the synced models. CloudKit container created in the Apple Developer portal.
- Sync scope (D9): `WordCard` (with denormalized `sourceSnapshots`), `ReviewEvent` (or whatever the SRS history entity is called in lemma-level SRS), `AppSettings`.
- Out of sync: `Page`, `Sentence`, image bytes.
- Conflict policy (D10): every synced field has a sibling `*ModifiedAt: Date` attribute. On merge, compare timestamps and keep the later one. SwiftData doesn't natively give per-field LWW; implement via a small `Mergeable` protocol called from a `ModelContext` save observer.
- Schema requirement: every CloudKit-synced attribute must be optional or have a default. Audit the model accordingly.
- First-run sync: when user signs into iCloud post-install, SwiftData merges the cloud copy into the local store automatically. Test path: device A creates cards; device B installs and confirms cards appear.
- Toggleable: a Settings row "Sync with iCloud" with a default of ON when user is signed into iCloud. OFF detaches the model configuration on next launch.

### 3.7 Furigana button (Mecab-driven)

- Existing Mecab-Swift integration (PR #20, SHA-pinned PR #21) already produces tokens with kana readings.
- Reusable view: `JapaneseText(sentence: String, showFurigana: Binding<Bool>)`.
  - When `showFurigana == false`, renders plain text.
  - When `true`, runs Mecab tokenization (cached per sentence), renders ruby annotations using `AttributedString` with `.languageIdentifier("ja")` and `.rubyAnnotation` (iOS 17+).
- Button placement (D12): every screen that renders a Japanese sentence gets a `furiganaToggle` toolbar item.
  - Page detail / sentence list
  - Review/quiz screen
  - Word/lemma detail
  - Any future screen rendering JP text
- State: per-screen `@State` toggle, off by default, not persisted globally. (No global "always on" toggle in Settings for v0.3.0; user explicitly described it as button-driven.)
- Performance: tokenize lazily on first toggle-on per sentence; cache `[String: [Token]]` in a session-scoped store. Mecab is fast enough that pre-tokenization is unnecessary for typical page sizes.

## 5. Risks and Open Items

1. **CloudKit entitlement & developer portal**: requires manual steps in the Apple Developer portal to create the container before the first sync test. CI cannot do this. Note in the PR checklist.
2. **`AttributedString.rubyAnnotation` quirks**: cross-check rendering on small screen sizes; ruby may overflow line boxes. May need a custom `Text` layout in extreme cases.
3. **Gemini JSON drift**: dual-prompt outputs are bigger and more conditional. Add strict JSON-schema validation; on parse failure, fall back to error state with retry (existing PR #19 backoff covers HTTP, not malformed-JSON).
4. **Locale strings for endonyms**: shipping language picker labels in each language's endonym requires a small static map (`en` → "English", `tr` → "Türkçe", etc.) — not LLM-translated.
5. **Bundle id change ⇒ orphan store**: dev test data on existing devices is gone after first install of new build. Test on a clean simulator first.
6. **Gemini cost for build-time translations**: 7 bundled languages × ~50 keys × one-time per release = trivial. On-demand translations at runtime are also cheap.
7. **Unbundled language failure UX**: confirm the fallback (English + retry banner) is not a dead end. User can re-pick a different language from Settings.
8. **App Store metadata**: not in scope of code, but the rename will require new App Store Connect metadata when shipping. Note in the release checklist.
